# Reservation withdrawal with physical state and scoped authority

Synthetic reference boundary for a later replanning experiment. This block implements withdrawal, not a new scheduling policy. Existing experiments and their implied departure times are not rewritten. New reservation records explicitly carry commitment time, departure time, origin, work start and finish. One agent per operation; simultaneous crews are outside this lifecycle implementation. The existing scorer validates work, deadlines, travel, refusal and dependency closure.

Travel is already action. At time now, any reservation whose departure is at or before now is immutable, including in-transit, waiting-at-site, working and completed reservations. A later work start does not make an already departed agent cancellable. Unstarted work means departure strictly after now. Zero-distance reservations follow the same boundary: departure marks execution commitment, even if waiting for a predecessor.

Withdrawing a reservation also withdraws every later reservation in the same agent's append-only queue, because those routes were planned from the earlier destination. It also withdraws reservations depending on a withdrawn operation. Iterate both rules to closure. This conservative queue rule may discard otherwise salvageable work; no silent rerouting or retiming is permitted. If any closure member has already departed, reject the entire withdrawal. A downstream agent can already be in transit while awaiting upstream completion, so this check is essential.

A proposal lists the requested operations, complete withdrawal set, affected agents and immutable blockers. Application requires authority for every affected agent, not only the directly requested one. Authority here is an explicit supplied ID set in a trusted local simulator, not authentication or human consent. Bind proposals to the exact input snapshot and decision time with a SHA-256 fingerprint; reject stale state/time or altered closure. Recompute the proposal at application. Return a copied new reservation list and an audit record; never mutate caller state, erase completed work, or partially apply a rejected proposal.

Charge one logical withdrawal unit per removed reservation and report affected agents and removed future work occupancy. These are accounting components, not measured cancellation duration, money, CPU or energy. No physical travel is undone because already-departed reservations cannot be removed. A future policy study must separately specify how cancellation cost consumes resources and whether replanning is worth it.

Retain demonstrations of route/dependency cascades, missing authority, an in-transit downstream blocker, stale time, and preservation of completed work. Freeze source/dependency hashes before demonstrations. No agent-policy reruns, private data, messages or publication.
